## 📚 Project Overview

This project aims to integrates web scraping, API ingestion, data normalization, caching, data warehousing and intuitive graph-based analytics,
resulting in **unique cross-market insights** (segmentation/adjacency) and **personalized book recommendations** leveraging large amounts 
of aggregated literary data that would otherwise be innaccessible at such scale, details and quality.

Allow for different community/niches to interconnect and expand based on reading/reviewing-interest profiles !

> [!NOTE]  
> Originally a database engineering and ETL project, it evolved into a highly refined, cloud integrated  **Big Data platform** with ML and graph NoSQL analytics capabilities, optimizing both data ingestion and community insight generation.

**BookScrapeDB_Recommends** is a multi-source, large-scale literature analytics and recommendation platform that:
- Extracts data from many web sources combining APIs, concurrent crawlers and web scraping
- Builds an **automated ETL pipeline** to parse raw data into SQL DML or structured files for scalable DB/Warehouse population locally or on cloud
- **Automatic DML generation** for scalable DB population  
- Uses a **SQL warehouse** and **Neo4j Graph DB** for analytics (Cypher, GDS, GCP AuraDS)
- Generates **AI-assisted insights**, personalized book recommendations, and community influence networks  
- Combines **structured**, **semi-structured**, and **scraped** data to create **high-integrity literary datasets**
- **Google cloud platform** integration: VertexAI, CloudSQL, BigQuery, Batch Dataflow
- **AI & statistical models** for recommendation, sentiment, and market segmentation
- Statistically model: ratings scores, cross-genre trends, and various influence networks/clusters.  
- **Vector+Graph RAG Hybrid embeddings** for reviewer profiling and cross-genre insights using different LLMs

A comprehensive data engineering solution that aggregates, transforms, and analyzes literature data from multiple authoritative sources to generate:

- **For Readers**: Personalized book recommendations using collaborative filtering and sentiment analysis
- **For Authors/Publishers**: Market segmentation insights, cross-genre opportunities, and influence network analysis
- **For Analysts**: OLAP-ready data warehouse with graph-based visualizations of reading trends and community clusters

### 🎯 Key Technical Achievements, Scale, Impact

- 📚 **230GB+ raw data** stored and live processed in warehouse for integrity and actionability (several 100M books/catalogs data/reviews)
- 🧠 **9–15M+ graph nodes** used in real applications with NoSQL Graph recommenders used with AI
- 🧠 **100M+ nodes & relationships** available for recommenders in warehouse and visualized in Neo4j
- 🔁 **3-4 APIs + multi-thread crawlers** with caching and retry systems  
- ⚙️ 6 **major ETL codebase versions** since 2024, with reproducibility, caching, retry logic, and deterministic DML generation  
- 🕸️ Combines crowdsourced and authoritative data to map influence networks and predictive discoverability

### Data Engineering & ETL
- **Custom SQL DML Code Generator**: Automated INSERT statement generation for all entities (books, authors, reviews, genres, etc.)
- **Intelligent API Caching**: Persistent caching system reducing API calls by 95%+ and eliminating network flakiness
- **Multi-Source Crawlers**: Scrapy-based spiders with concurrent multi-threading and intelligent pairing algorithms
- **Data Quality Pipeline**: Cross-referencing, validation, and normalization across all data sources

### Analytics & Intelligence
- **Statistical Rating Models**: Probabilistic models for accurate reader profiling beyond simple averages
- **Graph Analytics**: PageRank algorithms identifying author influence networks and reading community clusters
- **Sentiment Analysis**: NLP-based review sentiment scoring across millions of user reviews
- **Cross-Genre Discovery**: Algorithmic identification of niche markets and adjacency opportunities

### Database Architecture
- **Relational (MySQL)**: Normalized schema optimized for OLAP queries and data integrity
- **Graph (Neo4j)**: Relationship-focused analytics with custom Cypher queries for pattern discovery
- **Hybrid Approach**: Leverages strengths of both SQL (transactions) and NoSQL (relationships)

## 🚀 Pipeline Workflow

```
┌─────────────────┐
│  Data Sources   │  APIs (cached) + Web Scraping (concurrent)
└────────┬────────┘
         │
    ┌────▼─────┐
    │ Raw Data │  JSON/HTML/XML → 1GB+ per concurrent run (Need respect Rate-limits, robot.txt, etc...)
    └────┬─────┘
         │
  ┌──────▼──────┐
  │   Parsers   │  Spark RDDs, API Caching, Regex, Formatters + Validators + Cross-referencers
  └──────┬──────┘
         │
┌────────▼─────────┐
│  DML Generator   │  6 major versions, See specific readme
└────────┬─────────┘
         │
    ┌────▼────┐
    │   SQL   │  Data Warehouse (OLAP-ready) (MySQL server cluster and/or GCP CloudSQL/BQ)
    └────┬────┘
         │
    ┌────▼────┐
    │  Neo4j  │  Graph Analytics + Visualizations, GDS, Python Network Visuals and WIP: Spark GraphX
    └─────────┘
```

## 📥 Base Database Setup & Population

### DML File Loading Order

The generated DML files **must** be executed in this exact order to maintain referential integrity:

```sql
1.  book_dml.sql          -- Core book entities
2.  person_dml.sql        -- Person records
3.  reviewer_dml.sql      -- Reviewer profiles
4.  author_dml.sql        -- Author information
5.  bookauthor_dml.sql    -- Book-Author relationships
6.  bookreview_dml.sql    -- Reviews junction
7.  characterr_dml.sql    -- Character entities
8.  bookcharacter_dml.sql -- Book-Character links
9.  genre_dml.sql         -- Genre taxonomy
10. bookgenre_dml.sql     -- Book-Genre classification
11. place_dml.sql         -- Geographic locations
12. bookplace_dml.sql     -- Book-Place associations
13. publisher_dml.sql     -- Publisher records
14. bookpublisher_dml.sql -- Book-Publisher links
15. series_dml.sql        -- Series metadata
16. bookseries_dml.sql    -- Book-Series relationships
17. subject_dml.sql       -- Subject headings
18. booksubject_dml.sql   -- Book-Subject indexing
19. listprice_dml.sql     -- List prices
20. retailprice_dml.sql   -- Retail prices
21. thumbnail_dml.sql     -- Image URLs
```

> [!IMPORTANT]  
> DML scripts must be executed in order (book → author → genre → etc.) for base/minimal DB, otherwise revisit both schemas/models and ETL in your new release/fork

## 🔧 Development Notes

### Performance Optimizations

1. **Caching Strategy**: All API requests cached in `spec_dict.json` for 95%+ faster processing
2. **Concurrent Crawling**: Multi-threaded spiders with intelligent rate limiting
3. **Hashable Data Structures**: Optimized lookups for cross-referencing across datasets
4. **Incremental Processing**: Supports partial updates without full regeneration
5. See issues about integrating Spark GraphX with Neo4j Analytics engine at scale
6. For SQL server low-level DB tuning and configs, see `mysql.cnf`
